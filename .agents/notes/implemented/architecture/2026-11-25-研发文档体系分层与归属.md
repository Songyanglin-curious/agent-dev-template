# Agent Note: 研发文档体系的分层与归属

Status: implemented

## Problem

此前的 agent-docs 把文档维护当成独立于研发的活动：研发输入、设计取舍、系统认知和工程经验混在同一批文档里，同一个事实会在多处重复，人和 Agent 都无法判断一次改动应更新哪一份；研发结束后再补文档，文档与代码脱节，积累的知识也不参与后续研发。仓库需要一套按研发过程组织的归属结构，让正确的信息只有一个写入位置，其他位置只做引用。

## Decision

研发信息分成四层，每层只有一个归属方。

| 层 | 归属 | 承载的事实 | 生命周期 |
|---|---|---|---|
| 研发输入 | `研发输入/` | 原始需求、外部约束、参考资料、梳理草稿 | 随需求变化，可整份删除 |
| 研发演进 | `.agents/notes/` | 问题、方案、取舍、后果、被否决的方案 | proposed → implemented → archived；rejected 作为护栏 |
| 系统认知 | `docs/architecture.md`、`docs/subsystems/`、`<module>/README.md`、`docs/persistence-changes/` | 系统组成与依赖、能力与类型契约、模块使用与限制、历史数据结构 | 持续同步，只描述当前状态 |
| 工程知识 | `docs/core-guidelines/`、`docs/defensive-patterns/`、`docs/cookbook/`、`docs/postmortem/`、`.agents/skills/` | 设计规则、缺陷模式、操作步骤、事故经过、场景工作流 | 按需增删，由评审与门禁维护 |

系统认知分三层：架构回答“系统由什么组成、如何协作”，子系统回答“某项能力具有什么精确语义和契约”，模块回答“这个软件单元提供什么、如何使用、边界在哪里”。模块文档随模块代码维护，在模块具有独立职责和独立维护价值时建立；模块组文档只在模块分组需要被一起理解时建立。`scripts/README.md` 是模块层的当前实例，`docs/subsystems/` 承载文档门禁能力。

研发演进以一次决策为单位，不按对话或任务记录。implemented 记录用现在时描述已交付的现实，并随路径、符号和默认值同步更新；被完全取代的记录可以合并删除，值得留存的历史进入冻结的 `archived/`。

工程知识按“参与研发的方式”分工：core-guidelines 是设计与编写时必须遵守的规则，defensive-patterns 是修改某类工件前必须核对的缺陷模式，cookbook 是已经验证过的固定操作步骤，postmortem 是事故经过与系统性根因，Skills 规定在什么场景下如何使用这些知识。

治理层不属于任何一层：根 `AGENTS.md` 承载每次会话都需要的触发规则，`docs/AGENTS.md` 承载文档标准，`scripts/` 承载能机械判定的结构约束。

## Alternatives considered

**按文档类型建目录（requirements/design/decisions/guides）。** 这种划分来自写作体裁，不来自研发活动。Agent 在修改代码时仍然要跨四个目录判断影响面，重复和遗漏不会减少。

**把所有知识放进一个 `docs/` 树，用子目录区分层级。** 目录深度无法表达归属关系；同一层的文档会逐渐互相复述，而模块文档必须随代码移动，放在集中的 docs 树里会失去就近维护的优势。

**只保留 Agent Notes，不建立系统认知文档。** Agent Notes 记录的是为什么，无法替代“当前系统是什么”的稳定契约；每次研发都要从代码重新推导系统行为，成本更高。

**照搬 DSH 的全部文档类型。** DSH 的双语文档配对、文档网站、TypeScript 类型等价检查都依附于它自己的技术栈和发布方式；本项目面向不同语言和项目结构，照搬会引入无法维护的空机制。

## Consequences

收益是事实只有一个写入位置，重复内容可以被搜索和评审发现；决策理由与当前系统分离，读者不必在现状文档里筛选历史；模块文档随代码移动，减少失效链接；每层可以独立增删，不牵动其他层。

代价是四层结构对小型项目偏重。模块组、复盘和持久化记录按需建立，没有相应事实时不建目录。归属判断仍然需要语义能力，门禁只能检查结构与引用，不能判断一句话该不该写。另一个风险是为了填满层级而写低价值文档；规则要求只从真实研发活动中产生归属内容，空白层级不保留占位。模块检查按 `kind` 发现文档；未声明元数据的 README 不进入自动检查，由评审兜底。

## Verification

`docs/AGENTS.md` 的层级表覆盖四层与治理层，每一行只有一处归属；`pnpm run test:docs` 校验元数据、模块与模块组结构、子系统关联、链接与锚点、字数预算；`pnpm run test:notes` 校验本记录的生命周期与格式。
