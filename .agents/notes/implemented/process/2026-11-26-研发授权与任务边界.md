# Agent Note: 研发授权与任务边界

Status: implemented

## Problem

此前的 `dev-workflow` 把非机械性研发收进一条统一流程：明确问题、定位影响面、判断提案、实施、同步文档、沉淀知识、验证、交付。它重复了根 `AGENTS.md`、`docs/AGENTS.md`、Agent Note 规则和 Scripts 已经拥有的内容，也让简单任务先进入一套总流程。更关键的是，它没有明确区分调查与实施：Agent 可能把“调查一下”理解成实施授权，也可能在实施中不断扩大范围。

DSH 的做法不是统一流程，而是根规则按任务触发专项技能，具体风险由对应 Skill、Scripts 和人工审查约束。本项目需要采用同样的方向，同时补上本地 Git 环境缺少 PR 审查时的任务边界。

## Decision

根 `AGENTS.md` 的“任务与授权”规则承担常驻边界：

- 调查、研究、讨论默认只读。
- 实施任务在明确范围内自主完成必要修改；范围不清时先说明或询问。
- 不擅自扩大任务目标、改变重要约束或外部契约；发现必须改变时先说明原因、影响和方案。
- 按实际变更触发文档、Note 和专项规则。
- 按变更范围选择必要检查；交付说明实际变更、验证、风险和状态；交付不等于发布。

删除 `dev-workflow`。它没有独立职责：触发归根 `AGENTS.md`，文档维护归 `docs/AGENTS.md`，Note 归 `.agents/notes/README.md`，机械检查归 Scripts，固定步骤归 cookbook。专项 Skill 只在出现需要多步判断、会重复出现、现有规则无法承载的能力时建立；不为了填补流程而拆分薄 Skill。

原始输入、研发任务和 Agent Note 分开：

- `研发输入/` 保存外部要求、约束和参考资料，不保存已确认决策。
- 研发任务描述本次目标、范围、验收和状态；任务层后来由 [轻量研发任务管理](2026-11-27-轻量研发任务管理.md) 落地，本记录保留授权边界。
- Agent Note 保存长期决策理由、替代方案和后果，不承担任务状态、原始输入存档或交付报告。
- 三者通过相对链接关联，不复制内容，不建 Issue 系统。

任务范围包括实现目标所必需的代码、测试、文档和配置。正常技术选择和必要关联修改不反复请求确认；跨模块本身不是高风险，风险来自是否超出任务目标、改变未要求的外部契约、影响未预期消费者，或触及持久化、安全、外部操作等专项风险。明确要求的高风险变更按专项规则实施，不因风险本身重复申请泛化授权。

交付说明不设固定模板：简单任务说明实际变更和验证结果，复杂任务补充影响范围、风险、遗留和 diff 导航。任务文件内的最终交付记录见 [轻量研发任务管理](2026-11-27-轻量研发任务管理.md)；交付说明仍按事实陈述状态，不建立额外的交付状态机。

## Alternatives considered

**保留 `dev-workflow` 作为机制选择参考。** 它仍会要求所有非机械任务先进入一个入口，继续重复根规则和 docs 的内容，并倾向于把参考变成流水线。

**把 `dev-workflow` 拆成五个专项 Skill。** 代码审查、Git 操作、发布部署等能力目前没有足够的真实场景和稳定程序；先拆会制造五个薄 Skill，增加维护面而不是约束。

**采用完整 Issue/PR 系统。** 本地项目和普通 Git 环境不一定有协作平台；编号、标签、优先级、状态流转和审批会引入与研发活动不成比例的负担。链接和 Git diff 已能承担最小追溯。

**把所有跨模块修改都视为高风险并要求确认。** 任务明确要求修改跨模块协议时，契约变更本身就是任务目标；重复确认会阻碍正常研发。真正需要暂停的是未要求的契约变化、未预期消费者和专项风险。

**为交付建立固定模板和状态枚举。** 简单任务会被迫生成报告，状态词也会变成形式。保留信息维度，按任务复杂度决定详略，更符合实际使用。

## Consequences

收益是根规则更短、职责更清楚，不再存在一条所有任务都要经过的总流程；调查与实施的边界明确，任务范围成为自主工作的依据；原始输入、任务和 Note 不再互相兼任；专项 Skill 的建立有明确门槛。

代价是 Agent 需要自己判断任务性质并选择机制，不再有一个总入口告诉它先做什么；根 `AGENTS.md` 必须承担触发和边界，不能退回成长篇流程；现有 Skills 和 Scripts 的缺口会暴露出来，需要逐项评审，而不是用新流程掩盖。

## Verification

- `pnpm run test:notes` 校验 Agent Note 的格式与生命周期。
- `pnpm run test:gates` 校验关键门禁的失败路径。
- `pnpm run test:docs` 覆盖文档链接、预算、模块与子系统关联以及变更影响清单。
- 活动文档不再引用 `dev-workflow`；`研发输入/` 中的历史调查材料保留原文，不作为当前规则。
