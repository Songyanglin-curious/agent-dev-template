# Agent Note: 第一版研发协作机制

Status: implemented

## Problem

删除 `dev-workflow` 后，根 `AGENTS.md` 只保留任务边界和触发规则，代码审查、变更范围识别、检查选择和项目接入没有具体程序。现有 Scripts 主要检查文档结构，不能回答“这次改了什么、该跑哪些检查、评审先看什么、已有项目如何建立最小系统认知”。直接复制 DSH 的 Skill 会把 DSH 的包、类型和 PR 假设带进来；继续只写规则又会让这些能力停留在愿望层面。

## Decision

第一版增加四个按任务触发的机制，不建立统一流程：

- `scripts/change-scope.ts`：按基线输出 committed、staged、unstaged、untracked 路径，作为评审和检查选择的共同输入；它只报告路径，不判断文档归属或检查项。配套 `test:tools` 覆盖路径分类、无效基线和缺失参数。
- `pre-push-checks` Skill：先建立变更范围，再按文档、Note、门禁、工具、代码、持久化、依赖构建、UI 等面选择最小证据；不默认全量，不重复已通过检查，失败停止；本地 Git 只提交本次文件，历史重写使用 `--force-with-lease`，推送后核对远端。
- `code-review` Skill：先读任务、归属规则和文档，再读完整 diff；按触及面检查行为、契约、所有权、生命周期、数据、安全、测试和文档；用 defect/location/impact/evidence 报告 blocker 与 suggestion；明确不是逐项打勾的完整清单。
- `project-onboarding` Skill：空项目从目标、约束和最小架构自然生长；已有项目先保护旧资料，再以入口、构建、测试、配置、数据和调用关系调查候选单元，由人确认架构、模块和子系统边界，最后建立最小文档和初始 Note。

根 `AGENTS.md` 负责触发这些 Skill 和命令；`docs/architecture.md` 说明变更范围与检查选择的位置；CI 增加 `test:tools`。文档同步继续使用 `verify-change-docs` 的提醒模式，不把全部 `remind` 提升为 `require`；未覆盖的规则、零语料和失败路径缺口登记在 proposed Note。

## Alternatives considered

**只保留根规则，不增加 Skill 和工具。** 代码审查、检查选择和项目接入需要多步判断和证据，单条常驻规则无法承载；Agent 会各自发明做法。

**直接复制 DSH 的 `dsh-code-review` 和 `dsh-pre-push-checks`。** 它们依赖 DSH 的包结构、PR、测试栈和 GitHub 命令；直接复制会把无关假设带进模板。这里保留“先范围、后依据、按面选证据”的结构，改写为本地 Git 和通用项目语言。

**继续维护一个统一研发流程。** 会让简单任务先进入总流程，重复根规则和 docs 的内容；第一版继续采用触发式机制。

**把所有文档提醒改成强制失败。** 语义影响无法靠路径可靠判断，过宽的 `require` 会产生噪音和虚假的文档修改；先保留提醒并记录缺口。

## Consequences

收益是评审、检查选择和项目接入有了可执行入口，同时没有恢复统一流水线；`change-scope` 为后续检查选择提供共同事实；项目接入明确要求代码证据和人工确认，避免按目录批量生成文档。

代价是多出三个 Skill 和一个工具，需要真实任务验证是否过重；`change-scope` 需要可解析基线和 Git 仓库；`code-review` 仍是通用指南，具体项目的审查面需要按技术栈补充；文档同步仍不是强制门禁，遗漏仍可能发生。

## Verification

- `pnpm run test:tools` 覆盖 `change-scope` 的路径分类、无效基线和缺失参数。
- `pnpm run test:gates` 覆盖现有门禁失败路径和仓库引用排除。
- `pnpm run test:docs` 校验新增 Skill 链接、文档预算、模块与子系统关联。
- `pnpm run test:notes` 校验本记录和现有 Note。
- `change-scope` 的实际基线输出由使用者的分支状态验证，不在固定测试中伪造。
