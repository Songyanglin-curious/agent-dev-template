# 模板：module

用于模块所属位置附近的模块说明（通常为 `<module>/README.md`；具体位置由项目模块组织决定）。模块是具有独立职责和维护价值的软件单元，代码目录、入口和部署形态不是固定条件，具体形态由模块文档说明。模块文档帮助人和 agent 认识模块提供什么能力、何时选用、如何接入、遵守什么行为契约、边界在哪里、依赖什么、内部如何组织，以及如何从文档走到源码。它不重复系统级的架构叙述、所属子系统的类型定义，也不承载决策历史。这是模块类文档的基础模板；模块是服务、库、插件、工具还是脚本，不改变本模板。不是每个代码目录都需要模块文档：只在模块具有独立职责、稳定边界和独立认知或维护价值时建立。

## Frontmatter

```yaml
---
description: "该模块提供的能力，以及读者应在何时打开这份文档；用一到两个具体句子写清可搜索的领域术语。"
kind: "module"
---
```

## 规则

- **先核验再落笔。** 执行文档将要展示的每条命令、配置字段和示例，复现默认值、警告和失败模式；删掉任何未能复现的内容。字段清单链接生成的配置目录，而不是凭源码阅读复述。
- **能力说明面向使用者。** 写读者能做什么、何时选用、与相邻模块如何分界；不写内部角色、组件拆分或注册项。除非读者会直接在配置、命令或公共 API 中使用，否则省略源码标识符。
- **使用方式按形态写。** 有安装机制的模块写经过验证的安装路径；没有安装机制的模块只写实际的调用、加载或启动方式，不得出现不存在的安装命令，也不得把可执行形态写成库用法。
- **行为契约是承重内容。** 失败、持久性、并发、安全和性能限制不能因为“常见路径用不到”而省略；模型可见的效果写明归属方，不复制别处的措辞。
- **职责边界防止重复。** 只写本模块负责什么、不负责什么，并链接相邻归属方；跨模块的行为归上层系统文档，类型与语义归所属子系统页面，决策理由归 Agent Note。
- **内部设计停留在概念层面。** 折叠区给设计理念、组成、数据流和依赖方向，再加源码导航表；源码导航每行一个路径和一行职责，指向提供精确细节的文件。依赖全貌链接架构文档，不复制依赖图。
- **章节顺序固定。** `已知限制与暂缓工作` 是最后一个内容 H2，`Dev Note` 是其中折叠的 H3；`Further Exploration` 放在限制章节之前。
- **Summary 与限制章节受门禁约束。** Summary 不超过 100 个词等量（英文按空白分词，中文按每两字一个词等量），`已知限制与暂缓工作` 与 Summary 同由 `verify-module-readmes` 校验；没有限制时在 `scripts/module-readme-limitations.allowlist.json` 登记理由。
- **同一次变更内维护引用。** 修改模块文档时同步更新入站链接、索引条目和受影响的生成产物；移动或重命名文档时原子完成，不留失效链接。
