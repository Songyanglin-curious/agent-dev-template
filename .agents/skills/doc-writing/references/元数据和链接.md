# 元数据和链接

## 摘要

README 元数据供检索和选择模板使用。`kind` 字段选定本技能中唯一的 README 模板，并映射到相应的文档规范。文件命名惯例或实际运行的校验已经负责的字段，无需放进 frontmatter。

## README 元数据

手写 README 都以 YAML frontmatter 开头。允许自定义字段，通用字段保持稳定，以便搜索和索引。

```yaml
---
description: "说明用户和维护者在选用、配置或排查这个包时可使用的能力。"
kind: "package-reference"
---
```

双语包 README 必须包含 `description` 和 `kind`。页面标题和包清单已给出名称，文档的用途及阅读路径已体现目标读者，重复写进 frontmatter 无助于检索。对应文档路径由同级文件名 `README.zh.md` 确定，配对状态由伴随文件负责，因此 README 内无需 `i18n` 元数据。只有仓库维护的分类系统和搜索消费者确实需要超出描述和全文搜索的分类时，才添加 `tags`。除非现有负责方另有拼写规定，键名使用小写并用连字符分隔。不要把经常变动的代码清单放进 frontmatter。

## 文档类型体系

`kind` 直接选择文档模板。每个类型只对应本技能内的一个模板，每个模板均有对应类型。`docs/persistence-changes/YYYY-MM-DD-slug.md` 使用 `persistence-change`。`docs/persistence-changes/releases/dsh-v*.md` 使用 `persistence-release`。`docs/persistence-changes/historical-formats/vN.md` 使用 `persistence-format`。相应中文文档沿用同一个类型。`docs/upgrade-guide/v<version>/<item>/guide.md` 和其 `guide.zh.md` 使用 `upgrade-guide`。目录 README 用作索引。包 README 的类型依序按规则推导：

1. `packages/README.md` 或 `packages/<group>/README.md` → `package-group`。
2. 包清单声明 `dsh.bundle.patch` → `package-bundle`。
3. 包出现在 `scripts/doc-standard.spec.ts` 的受审计库登记表 → `package-library`。
4. 其余包（默认导出服务或导出 `apply` 的插件）→ `package-reference`。

| `kind`                | 仓库位置                                                                    | 模板                                                       | 规范                                                                                                                                                      |
| ----------------------- | --------------------------------------------------------------------------- | ---------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `package-group`       | `packages/README.md`、`packages/<group>/README.md`                      | [package-group.md](../templates/package-group.md)             | 包组索引介绍能力类别、列出直接下属包、解释组合关系，并链接由各包负责的细节。                                                                              |
| `package-reference`   | 有插件入口的 `packages/<group>/<package>/README.md`                       | [package-reference.md](../templates/package-reference.md)     | 包契约遵循[包 README 评审标准](review.md#package-readme-review)及权威的[包文档要求](../../../../docs/cookbook/adding-a-package.md#4-write-the-package-readme)。 |
| `package-library`     | 有普通模块入口的 `packages/<group>/<package>/README.md`                   | [package-library.md](../templates/package-library.md)         | 库契约说明消费者入口及边界，无配置档安装路径或挂载配置。                                                                                                  |
| `package-bundle`      | 对应包声明 `dsh.bundle.patch` 的 `packages/<group>/<package>/README.md` | [package-bundle.md](../templates/package-bundle.md)           | 可安装的层，涵盖经过验证的 `dsh plugin` 安装路径、层的语义和补丁文档。                                                                                  |
| `persistence-change`  | `docs/persistence-changes/YYYY-MM-DD-slug.md` 和中文对应文档              | [persistence-change.md](../templates/persistence-change.md)   | 历史确认记录，涵盖自动检测的类型变更、各根类型的前序记录、兼容性决定和生成的变更后 schema。                                                               |
| `persistence-release` | `docs/persistence-changes/releases/dsh-v*.md` 和中文对应文档              | [persistence-release.md](../templates/persistence-release.md) | 回溯观察，涵盖固定标签、相邻版本的前后摘要、实际版本常量和有变化的变更后 schema，不作兼容性确认。                                                         |
| `persistence-format`  | `docs/persistence-changes/historical-formats/vN.md` 和中文对应文档        | [persistence-format.md](../templates/persistence-format.md)   | 选定的历史格式，涵盖来源证据、完整根 schema 和可达类型。当前写入器使用生成目录。                                                                          |
| `upgrade-guide`       | `docs/upgrade-guide/v<version>/<item>/guide.md` 和中文对应文档            | [upgrade-guide.md](../templates/upgrade-guide.md)             | 从目录标示的发行版本到下一版本的一项外部可感知的破坏性变更。英文在 500 词以内包含 `Change` 和 `Migration` 两节。                                      |

分配 `package-library` 或 `package-bundle` 前，检查 `package.json` 是否声明 `dsh.bundle.patch`，并在 `src/index.ts` 中确认入口形式。导出 `apply` 或默认导出服务的是插件，普通模块 API 属于库。`dsh plugin --profile <name> add <package>` 可以安装任意 npm 依赖，但只有声明 `dsh.bundle` 的包会在配置档协调时激活为一层。不要把该命令列作库或普通插件的安装路径。文档校验从同样的事实推导预期类型，拒绝其他值，也拒绝 `name`、`audience`、`tags` 和 README 内的 `i18n` 元数据。新增类型需要独立模板、明确的仓库位置或负责方，以及把文档映射到该类型的针对性校验。

## 描述质量

Agent 搜索 frontmatter 的 `description` 值，先筛选页面，再读取全文。像写技能描述一样交代页面涵盖什么和何时查阅。用一到两句具体表述，包含可检索的领域术语，并写清与相邻文档的分工。避免罗列所有章节、宣称优越、重复标题、写空泛宣传、记录变更历史或撰写技术状态报告。

合适：`已交付的 JSONL 会话持久化后端，供部署人员和维护者选用、配置或排查可选用 Zstandard 压缩的逐会话持久日志。`

不合适：`最好、最先进、拥有大量优化的会话存储实现。`

## 仓库链接与路径写法

链接目标应可以由机器校验。正文中提到的路径按讨论语境写。页内菜单只用片段链接，外部资源使用完整 URL。

理想的内部链接可以从仓库根目录指定目标，但以 `/docs/...` 开头的 Markdown URL 会被 GitHub 解析到仓库之外，网站转换器原样保留，`verify-md-links` 也会跳过它。在仓库的解析器能为所有渲染环境处理根路径前，Markdown 链接使用渲染器认可的相对 URL。正文可按语境提到 `docs/` 或 `packages/session/` 等逻辑路径。避免使用未经校验的前导斜杠链接。

## 双语逐行对齐

英文和简体中文具有同等权威性。frontmatter 键顺序、标题、空行、段落、列表项、表格、围栏、链接目标和实际总行数须一一匹配。英文侧的相对链接指向 `.md`。中文侧优先指向存在的 `.zh.md`，否则指向 `.md`。配对校验将两种目标视为同一文档。在对应的行内自然翻译，两种语言都不做硬换行。代码块逐字节一致。可调整首次提及时的术语注解位置，但须保持行结构。

行数相同只说明结构对齐。评审还要检查含义是否完整、术语是否准确、文字是否自然，以及每一行的命题是否一致。

## 双语一致性记录

每对双语文档保留 `*.i18n.yaml` 伴随文件。它为各标题分节记录一对内容哈希，排除围栏代码块和生成区域，因此修改不同章节时可使用 Git 的默认文本合并。生成数据放在生成区域，由生成器同时写进两份文档。`verify-translation-pairing` 将记录与现有内容对比，并校验结构。任一语言改动后，运行 `pnpm run verify-translation-pairing --write <pair>` 重录。内容哈希不要复制到 README frontmatter，否则独立改动会写到同一头部行，使原本可合并的正文在源文件中产生冲突。
