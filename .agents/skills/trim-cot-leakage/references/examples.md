# 泄漏示例与三档改写

以下示例校准审计中的判断尺度。每个示例给出三档：**删减过度**（为缩短篇幅牺牲了命题）、**过度详细**（保留了编写过程）、**平衡版**（保留契约，删除记录）。把它们当作判断原则的示例，不要当作可直接套用的文案模板。本文件故意引用泄漏措辞作为校准材料；[检索探针](recall-batteries.md)排除本目录，这些措辞在别处仍然算泄漏。

## 1. 缓存 JSDoc 的归属与时序

**场景：** 缓存模块的公开 JSDoc 解释 `get` 何时刷新条目。

**删减过度：** “`get` 返回缓存值。”——丢了刷新时机、写入归属和过期后的行为。

**过度详细：** “本次修改把刷新从写入时挪到读取时（评审中确认过），因此 `get` 在命中后会检查 TTL，过期就重新加载……”——把改动和评审过程写进了契约。

**平衡版：** “`get` 在命中后检查 TTL，过期时同步重新加载；未命中不写入，写入只发生在 `set`。重新加载失败时保留过期值，并把错误返回给调用方。”

**原则：** 归属、时序和失败行为是契约。删除“本次”“评审中”，保留“谁在何时写入、过期后发生什么”。

## 2. 公开 JSDoc 的失败情形

**场景：** HTTP 适配器的 `send` 方法有多个失败出口。

**删减过度：** “发送请求并返回响应。”——调用方看不到超时、解析失败和重试语义。

**过度详细：** “先校验 URL，再序列化 body，然后等待超时；这些步骤在本次重构中抽成了 helper，评审里讨论过顺序。”——实现步骤和评审过程都不属于调用方契约。

**平衡版：** “发送请求并返回响应。URL 无效或超时（默认 10 秒）时抛出 `RequestError`；响应已到达但解析失败时，错误携带原始响应体。非幂等请求的失败不可自动重试。”

**原则：** 公开 JSDoc 必须写失败情形、错误类型和调用方后果。内部校验顺序不是契约，除非它改变可观察行为。

## 3. 适配器字段映射

**场景：** 事件适配器把上游事件转换成内部变更记录。

**删减过度：** “把上游事件转换为内部变更。”——调用方不知道字段如何对应、缺失值用什么默认、未知类型会怎样。

**过度详细：** “本次把 `kind` 改成 `type`，因为上游 v2 改了字段名；旧代码的兼容分支已经删除。”——改名经过属于历史。

**平衡版：** “把上游事件转换为内部变更：`kind` 映射为 `type`，`at` 映射为 `occurredAt`（缺失时取接收时间），`id` 原样保留。未列出的字段丢弃；未知 `kind` 抛出 `MappingError`。”

**原则：** 字段映射、默认值和未知值行为是调用方依赖的契约。改名或迁移的来龙去脉归 Agent Note，不归适配器注释。

## 4. 命令的退出码与限制

**场景：** `migrate` 命令的帮助文本和模块注释。

**删减过度：** “`migrate` 应用迁移文件。”——丢了执行顺序、事务边界、退出码和不可回滚的限制。

**过度详细：** “命令先读取目录，再排序，然后逐个执行；这段逻辑在上一轮评审后从循环改成了递归。”——控制流复述和评审过程都不是用户契约。

**平衡版：** “`migrate` 按文件名升序应用 `migrations/` 中尚未执行的迁移，每个文件在独立事务中运行；失败时停止并返回退出码 1，已完成的迁移保持已应用。`--dry-run` 只打印计划，不写迁移表。迁移不可回滚。”

**原则：** 顺序、退出码、事务边界和不可逆限制都是契约，不能为了简短删掉；“上一轮评审后”则应当删除。

## 5. 配置项：链接理由，保留本地契约

**场景：** 配置参考中的 `flushInterval` 条目。

**删减过度：** “`flushInterval` 控制刷新间隔（见设计文档）。”——指向一个无法解析的名字，且丢了单位、默认值和关闭行为。

**过度详细：** “我们讨论过 5 秒还是 30 秒，最后选了 15 秒；如果以后量上来再调。”——评审讨论和未来计划都不是配置语义。

**平衡版：** “`flushInterval`（毫秒，默认 15000，最小 1000）：批量写盘的最大等待时间。设为 0 关闭定时刷新，只在缓冲区满时写盘。”

**原则：** 本地保留默认值、单位、边界和关闭行为；取舍理由链接到所属 Agent Note（归属规则见 [Agent Note 规范](../../../notes/README.md)），不要复制讨论过程。

## 6. 模块文档写当前职责

**场景：** 存储模块的 README 开头。

**删减过度：** “存储模块负责持久化。”——职责、边界和失败行为都消失了。

**过度详细：** “本次重构把存储拆成 `blob/` 和 `index/`；评审中否决了单文件方案；上一版 README 里的 `legacy/` 已经删除。”——把拆分过程、评审结论和删除记录写成了模块介绍。

**平衡版：** “存储模块负责对象写入与索引更新：`blob/` 保存内容，`index/` 保存可查询的元数据。写入先落 blob 再更新索引；索引更新失败时 blob 保留，由 `reconcile` 清理。查询不属于本模块，见 `query/`。”

**原则：** 模块文档写当前职责、边界和失败行为。拆分过程与被否决方案归 Agent Note 的 `## Alternatives considered`。

## 7. 生成摘要必须独立成立

**场景：** 从源码 JSDoc 抽取摘要的生成目录。

**删减过度：** 只把生成的摘要改成“读取配置。”——源 JSDoc 没有改，下次生成会覆盖，而且摘要丢了默认值与错误行为。

**过度详细：** 源 JSDoc 写“为支持本次新增的配置来源，`load` 现在会……”，生成的摘要继承编写过程。

**平衡版：** 先改源 JSDoc：“读取 `config.toml`；文件缺失时返回默认配置，格式错误时抛出 `ConfigError`。”再重新生成目录，使摘要脱离源码上下文仍然成立。

**原则：** 生成摘要是衍生物，改归属方再重新生成；被抽取的句子必须在目标表面上独立成立。

## 8. 故障复盘保留证据与因果

**场景：** 一次连接池耗尽事故的复盘。

**删减过度：** “服务因连接池耗尽而故障，已扩容。”——没有时间线、证据、根因和预防措施。

**过度详细：** “事后我们先看日志，再看监控，最后逐步 debug，发现……”——调试过程不是证据，也不建立因果。

**平衡版：** “14:02 连接池达到上限 20，排队请求开始超时；14:05 告警触发，14:20 扩容到 50 后恢复。根因是慢查询 `orders_by_status` 缺少索引，单次查询持有连接 30 秒；索引上线后，同等负载下连接数稳定在 6。预防措施：慢查询超过 5 秒告警，连接池使用率超过 80% 告警。”

**原则：** 复盘保留事件序列、证据、因果链、影响和预防措施；删除调试叙事与推测。“本次事件”指事故本身，是复盘时间线的一部分，不是版本印章。

## 9. 已实现的 Agent Note 保留验证证据

**场景：** 记录“列表接口改用游标分页”的已实现决策。

**删减过度：** “决策：使用游标分页。”——为什么放弃 offset、验证了什么，都不见了。

**过度详细：** 保留 `## Proposal`、分三步的迁移计划、验收标准清单，并写“评审中从 offset 改成了 cursor”。

**平衡版：** “`## Decision` 列表接口使用不透明游标分页，游标编码排序键与末条记录 id；`## Alternatives considered` 记录 offset 分页被否决的理由；`## Verification` 列出运行过的分页测试：空页、末页和游标失效三种情形。”

**原则：** 已实现记录保留决策、被否决方案和验证证据；删除计划、验收清单和评审过程，正文用现在时陈述已交付的现实。

## 10. 不要为字数删减

**场景：** 模块 README 超出字数预算时压缩缓存上限说明。

**删减过度：** “缓存上限 4 MiB；最大的生成模块 3.1 MiB。”——丢掉“实测”一词后，3.1 MiB 读起来像定义而不是观测值。

**过度详细：** “这个上限最初是 2 MiB，后来因为某次构建失败调到 4 MiB，评审里有人担心……”——调整过程属于提交历史。

**平衡版：** “缓存上限 4 MiB（实测：最大的生成模块 3.1 MiB，保留约 25% 余量）；超过上限的模块在构建阶段报错。”

**原则：** 字数更少不算改进。保留“实测”作为证据来源，保留超限失败行为；调整历史留在提交、Agent Note 或复盘中。

## 过度纠正陷阱速查

删减过度的版本常常不是“更短的正确版本”，而是悄悄换掉了命题。按下面四项复核：

- **义务变成认可。** “这些直接注册是待迁移的例外”删成“这些直接注册是已认可的例外”，把待办义务改成了现状背书。保留“待迁移”。
- **假设变成已交付。** “一个未来的 IPC shell 会重写 `spawn`”删掉“未来”后，读起来像该类已经存在。明确标注假设，而不是只去掉时态标记。
- **删掉真事实。** 一段话前半是记录、后半是耦合事实时，删从句而不是删整句；确认幸存的事实仍能被验证。
- **保留数字、丢掉来源。** 保留“4 MiB”和“3.1 MiB”却删掉“实测”后，观测值变成定义；证据词和数字一起保留。
