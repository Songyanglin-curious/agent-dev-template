# 删减推理过程泄漏

推理过程泄漏是指文字站在编写过程的立场、而不是仓库当前状态上说话：它引用只有编写者能看到的产物，叙述改动而不是现状，或者与一位已经离开的评审者争辩。修法不是一律删除——带有事实从句的段落，先把每个从句改写成在当前代码状态下成立，再删除周围的记录；没有事实从句的段落（审计编号、控制流复述）直接删除。**背景要求：** [prose-standard](../prose-standard/SKILL.md) 是本文所用“保留完整命题”规则的归属方；[Agent Note 规范](../../notes/README.md) 说明决策理由与备选方案应该写在哪里；[文档标准](../../../docs/AGENTS.md) 给出各文档层级的写作规则。本 Skill 是指导，不是脚本：分类、保留与改写都需要逐段判断。

## 唯一的测试

对每个可疑段落只问一句：**读者在当前代码状态下，没有任何会话记录、PR 讨论或未提交草稿可用时，能否解析每个引用并验证每个断言？** 不能，就把幸存的事实从句改写成从仓库视角独立成立的陈述，删除其余部分；能，就不是泄漏——但“可解析”只是本 Skill 的下限。README、模块文档和公开 JSDoc 面向当前状态，一段在这里可解析的变更故事仍然是变更叙述，按第 3 类处理。

## 八类泄漏

1. **失效的设计过程引用。** `(decision 7)`、`(audit C2)`、`design §4.7`、`plan §1.4`、阶段标签（`T4`、`W3`、`P-I`）、“设计台账”、“(B 结论)”。如果该决策有已提交的归属方，用名称和路径引用它；否则删掉引用，把它的事实从句改写成独立句。
2. **分支与 PR 视角。** “这个分支后续的 PR”“本 PR 新增”“上一个提交”。写明已交付的机制或扩展点；延期工作放进 `TODO` 或 issue 引用。
3. **变更叙述与版本印章。** “以前用”“不再”“旧的 X”，以及索引式印章（“v1”“这次改动”“今天”“现在”与过去状态对比）。只写当前行为；已修复的回归写成现在时反事实（“没有 X 时，会发生 Y”），不要写成仓库考古（“以前会 Y”）。
4. **评审过程编排。** “评审中否决：”“评审者确认”“本说明第 5 稿”“第 N 轮意见”。只保留幸存的决策与理由，写成普通事实；删除谁在何时说过。被否决方案的正规归宿是 Agent Note 的 `## Alternatives considered`（见[规范](../../notes/README.md)）。
5. **面向评审者的自我辩护。** “这个类型转换是安全的——它只是……”“这里是对的，因为……”。为自身正确性辩护的注释是在对评审者说话，不是对维护者说话。写出让代码安全的不变量；如果代码本身已经表明，就删除注释。
6. **复述与推导记录。** 控制流叙述（“先 X，再 Y”）、测试走查、显而易见分支的证明。删除；只保留不明显的契约或不变量。
7. **含糊措辞与规划残留。** “现在大概没问题”“应该够用”、没有标记的延期。升级为 `TODO`/`FIXME`，或写出真实的边界值；删除含糊措辞。
8. **编写语言残留。** 中文正文里夹带的英文过程碎片（`as discussed above`、`per review`、`---- private ----`），或英文文档里夹带的中文过程碎片（“设计稿”“上一轮”）。翻译或删除。

## 不属于泄漏的内容

只靠“像不像历史”删减会在两个方向出错：删掉仍有效的引用，保留已失效的引用。以下保留规则按原样执行，[示例](references/examples.md)逐条校准。

- **Issue 与 TODO 引用。** `#1470`、`TODO(name):`、“issue #N 负责后续”在当前状态可解析；在任何表面都保留，包括 README。不要把它们挪进 Agent Note。
- **Agent Note 与复盘中的已合并 PR、issue 引用。** 它们是证据，位置遵循[文档标准](../../../docs/AGENTS.md)对变更记录的归属。
- **抑制说明。** linter 抑制注释（如 `-- reason` 形式）、覆盖率忽略原因、空 catch 的说明是必需文字；原因是错的就改成对的，永不删除说明本身。
- **现在时反事实回归钉子。** “没有 X 时，会发生 Y”“朴素的 X 会……”。
- **实测边界。** “（实测：512 层嵌套 ≈ 0.15s）”为常量提供依据；“实测”一词承载证据来源。
- **运行时的旧/新状态。** “旧连接排空后，新连接才开始接受”描述切换期间的存活对象，不是仓库历史。
- **外部标准与拥有章节编号的已提交文档。** RFC 9110 §10.1.5 以及已提交文件中按节引用都可以；`§N` 禁令针对未提交的内部草稿。
- **项目口吻与体裁章节。** 作为项目口吻的“我们”；复盘按序记录的事件链；Agent Note 的备选方案章节。
- **验证证据。** 已实现记录中的测试结果、命令输出和失败复现是决策依据；删除计划清单时保留它们。

## 过度纠正陷阱

删减前先枚举段落的命题，再对照[示例](references/examples.md)里的过度纠正陷阱：把“待迁移”的义务删成“已认可”的现状、把假设性示例提升为已交付功能、连同记录一起删掉真事实、保留数字却丢掉实测来源。命题写在同一行时删从句而不是删整句；缩短一句话不等于保留它的情态、否定和归属。

## 工作流程

1. **确认范围与排除项。** 要求显式给出审计范围（目录、文件或命令输出）；没有范围就报告缺少输入并停止，不要推断成全仓库。范围始终排除 `.git/`、`node_modules/`、归档的 Agent Notes（`.agents/notes/archived/`）；生成的目录、摘要和快照是衍生产物，只能改所属源码、JSDoc 或模板后重新生成。归档笔记是冻结快照，不是当前权威。
2. **先只读审计，再逐条做语义判断。** 先读[文档标准](../../../docs/AGENTS.md)和范围内最密集的文字（模块 JSDoc、README、Agent Note、复盘、Skill 文件），再跑[检索探针](references/recall-batteries.md)。探针只负责发现候选，不定义泄漏：每个探针先用已知正例、再用近似的反例校准，命中后逐条判断这段话站在谁的立场、承载哪些命题。评审和审计任务只报告发现；只有明确要求写、修复或删减时才应用改动。
3. **先改归属方，再改衍生物。** 生成摘要从来源 JSDoc 或模板抽取时，先修正来源，使被抽取的句子脱离上下文仍然成立，再重新生成所有衍生物。模块文档保留本地契约（调用方式、失败、限制、时序），把架构和理由链接到所属文档；配置说明保留默认值、单位和边界，把取舍链接到 Agent Note。
4. **删除前枚举命题。** 逐项确认执行者、动作、条件、时序、情态（`must`、`may`、`never`）、否定性保证、归属、副作用、失败模式和后置结果都还在。只删形容词、重复和叙述；字数更少不算改进。
5. **结束前验证。** 重跑检索探针，期望只剩受保留规则保护的内容、本 Skill 目录自身（示例故意引用泄漏措辞作校准）以及被引用的原文；逐个打开链接确认目标存在；确认剩余引用在当前代码状态下可解析；运行仓库已有的 Markdown、链接和 Agent Note 校验；无法安全改写的候选项列为延期并写明理由，不要为了完成审计而弱化命题。

## 报告

报告审计范围、实际改动、刻意保留的内容、延期项与已运行的检查；无法确定的段落单独列出，不要用“更简洁”作为删除事实的理由。
