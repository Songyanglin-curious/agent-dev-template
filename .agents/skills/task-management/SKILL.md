# 研发任务管理

## 何时使用

在以下情况加载本 Skill：

- 一项工作已经形成明确目标，需要记录范围、验收和进展；
- 外部输入或对话需要转成可执行任务；
- 任务需要交付、放弃或被新任务替代；
- 需要检查任务状态、目录和引用是否一致。

普通问答、机械修改和一次性小改动不创建任务文件。简单任务可以直接在对话中完成，并在最终交付说明中报告。

## 先读边界

- [研发任务规则](../../../研发任务/README.md)：目录、状态和文件结构。
- [任务模板](templates/task.md)：创建任务时复制骨架。
- [研发输入规则](../../../研发输入/README.md)：外部原始材料，不是任务或决策。
- [Agent Note 规则](../../notes/README.md)：长期决策理由，不承担任务进度。

任务记录“这次做什么、做到哪里、交付了什么”；输入保存外部要求；Agent Note 保存“为什么这样决定”。三者用相对链接关联，不复制原文。

## 创建任务

1. 从输入或对话中提取目标、背景、范围、验收条件和关联输入。
2. 选择 `YYYY-MM-DD-<简短标题>.md` 文件名，在 `研发任务/进行中/` 创建文件。
3. 按 [任务模板](templates/task.md) 填写 `status: 进行中` 和必需章节。
4. 在 `## 关联输入` 中用相对链接引用输入；没有外部输入时写明内部目标。
5. 只创建一份任务文件；需要长期决策理由时另建 Agent Note，不在任务中复制。

## 推进任务

- 在原文件中更新范围、验收、进展、阻塞和关联输入；不要新建“进展报告”或第二份任务文件。
- 范围发生变化时，先判断是否仍是同一任务；目标已改变时，新建任务并把旧任务标为 `已替代`。
- 发现需要长期决策理由时，建立或更新 Agent Note，并从任务链接过去。
- 状态仍为 `进行中` 时，文件保持在 `进行中/`。

## 交付、放弃与替代

状态变化时移动原文件，不复制文件。移动后修复任务中的相对链接。

### 已交付

1. 填写实际交付结果、验证结果和遗留问题。
2. 把 `status` 改为 `已交付`。
3. 将文件移动到 `研发任务/归档/已交付/`。
4. 运行 `pnpm run verify-tasks`。

### 已放弃

1. 在任务中增加 `## 放弃原因`，说明原因和已完成边界。
2. 把 `status` 改为 `已放弃`。
3. 将文件移动到 `研发任务/归档/已放弃/`。
4. 运行 `pnpm run verify-tasks`。

### 已替代

1. 在任务中增加 `## 替代关系`，用相对链接指向替代它的新任务。
2. 把 `status` 改为 `已替代`。
3. 将文件移动到 `研发任务/归档/已替代/`。
4. 确认替代任务真实存在，运行 `pnpm run verify-tasks`。

终态任务不回到 `进行中/`。需要继续工作时新建任务；旧任务按实际情况保留为 `已交付` 或进入 `已替代/`。

## 校验

```sh
pnpm run verify-tasks
```

门禁检查目录、文件名、`status` 与目录、必需章节、终态补充章节、替代任务引用和本地链接。脚本不判断任务是否真正完成，也不判断交付质量。

## 不做什么

- 不做任务编号、优先级、负责人、标签、评论、看板或自动状态机。
- 不为普通问答创建任务文件。
- 不把 Agent Note 改写为任务日志。
- 不复制输入原文到任务；用链接引用。
- 不建立集中任务索引；目录和搜索就是入口。
