前两类解决的是 Agent **如何进入项目、如何开展工作**；后三类解决的是 Agent **如何正确地开展研发工作**。

## **与其他研发模块的关系**

**其他文档负责保存知识和规则的详细内容，根目录 AGENTS.md 负责让 Agent 在适当的时候使用它们。**

例如，原文中实际存在以下关联：

| 研发活动                      | AGENTS.md 指定的行为           |
| ----------------------------- | ------------------------------ |
| 修改 `packages/`            | 先阅读 Architecture            |
| 新增或修改 Session Projection | 使用对应的 Skill               |
| 修改错误处理机制              | 使用错误处理 Skill             |
| 修改并发、生命周期、远程服务  | 阅读防御性模式                 |
| 产生具有长期价值的设计决策    | 创建或更新 Agent Note          |
| 修改代码及其契约              | 同步维护 README 和 JSDoc       |
| 准备推送代码                  | 使用 pre-push Skill 选择检查项 |
| 完成研发工作                  | 根据核心开发准则进行自审       |

这些并不是简单的文档索引，而是具有**研发活动触发条件**的指令。

**模板
