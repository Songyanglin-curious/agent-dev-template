## 核心原则

> 每个事实只有一个主要归属位置。明确什么文档对什么信息负责

## 四套相互协作的文档体系

* **系统认知体系 (认识当前软件系统)**
  架构
  子系统
  模块
* **研发演进体系（研究问题、提出方案、形成决策、保存研发依据）**
  提议中
  已实施
  已拒绝
  已归档
* **工程治理体系（约束开发行为，保证软件和文档质量）**
  AGENTS
  Skills
  核心准则
  防御模式
* **工程支撑体系(提供工程经验、操作方法和使用指导)**
  故障复盘
  示例集
  开发
  用户文档


| 核心认识                 | 对我们的价值                 |
| ------------------------ | ---------------------------- |
| 文档具有明确的职责       | 避免同一信息反复记录         |
| 文档参与研发活动         | 不再只是开发结束后的整理工作 |
| 不同文档具有不同生命周期 | 避免所有内容都需要永久维护   |
| 文档治理本身是工程活动   | 不完全依靠 AI 的主观判断     |
