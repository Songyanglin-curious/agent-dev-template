# 研发输入

本目录保存研发开始之前的原始材料：需求、缺陷报告、外部约束、参考资料和梳理草稿。它回答“为什么要做、依据什么”，不是当前系统的权威描述，也不保存已经确认的决策。

## 归属

- **放在这里**：客户或产品需求、验收标准、外部接口文档、协议规范、竞品资料、调研原文、尚未形成结论的梳理。
- **不放在这里**：已验证的设计决策（→ `.agents/notes/`）、系统当前行为（→ `docs/`）、可执行的操作步骤（→ `docs/cookbook/`）、重复出现的缺陷模式（→ `docs/defensive-patterns/`）。

材料被采纳为任务或决策后，用相对链接关联到 [研发任务](../研发任务/README.md) 或 Agent Note 的 `## Problem`，并说明采纳范围；不要在原文件上追加结论，也不要复制一份到 `docs/`。`研发任务/` 记录本次目标、范围、进展和交付，不复制原始输入。

## 组织

按来源或主题分目录，保留原始文件名和内容。可以增加一份同目录说明，记录来源、时间和已知偏差；说明本身不是需求文档。外部资料注明获取方式、版本或链接，使后续读者能判断它是否仍然适用。

## 生命周期

输入随需求变化。已失效的材料整份删除或移入按需建立的 `归档/` 子目录，不长期保留在活跃目录中；被决策引用的材料在决策记录中已经留有链接和理由，删除前先检查入站引用。`研发输入/` 不进入文档字数预算和链接检查，但其中的 Markdown 仍应符合基本写作规则。
