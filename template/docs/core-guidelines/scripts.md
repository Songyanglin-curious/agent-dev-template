# 脚本与门禁准则

<a id="s1-门禁以退出码和可定位诊断报告结果"></a>
## S.1 门禁以退出码和可定位诊断报告结果

**要求**：门禁通过时以 0 退出并打印一行摘要；失败时以非零退出，向 stderr 输出每条违规的文件、行号（可得时）和期望值。不得用日志中的警告代替失败，也不得在失败后继续写出成功摘要。

**理由**：自动化只能消费退出码；只打印警告的门禁在 CI 中等于没有运行。缺少文件与行号的诊断会迫使读者重跑或重读脚本，抵消自动化节省的时间。

**判据**：脚本在发现违规后仍以 0 退出；失败信息只写“校验失败”而没有位置；成功与失败摘要同时出现在同一次输出中。

**边界**：需要人工决定的语义判断不写成门禁；它属于评审或 Skill，不应为了自动化而降低为字符串匹配。

<a id="s2-共享解析只实现一次"></a>
## S.2 共享解析只实现一次

**要求**：Markdown 解析、frontmatter、标题、章节、链接、表格、文件发现和字数口径只在共享模块中实现。门禁脚本调用共享函数，不复制解析逻辑，也不各自维护文件遍历。

**理由**：解析口径的细微差异会让不同门禁对同一文件给出矛盾结论；修复一个解析缺陷需要改多处，且容易漏掉某个门禁。

**判据**：两个门禁中出现相同的正则、遍历或 frontmatter 解析代码；共享模块已经提供的能力被重新实现；同一文件在不同门禁中的语料集合不一致。

**边界**：一次性诊断脚本可以不复用共享模块，但不得进入 `test:docs` 或 `test:notes`。

<a id="s3-语料由清单和-glob-决定"></a>
## S.3 语料由清单和 glob 决定

**要求**：门禁扫描哪些文件由清单或 glob 决定，并在摘要中报告实际检查的数量。不得在脚本中硬编码文件列表，也不得在语料为空时静默通过。

**理由**：硬编码列表会在文件移动后悄悄漏检；语料为空时仍然输出“全部通过”会把配置错误伪装成成功。

**判据**：脚本内部出现具体文档路径数组；新增同类文件后门禁计数不变；摘要没有检查数量。

**边界**：清单本身是配置，可以列出具体路径；它必须由门禁校验失效条目和缺失文件。
