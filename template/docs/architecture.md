# 项目架构

这页是查找项目能力、职责边界和修改入口的起点。下表由接入项目填写；表后是随模板提供的研发工具，不代表项目的运行时组成。

## 接入项目填写

按 [project-onboarding](../.agents/skills/project-onboarding/SKILL.md) 调查当前实现。用能打开的源码、配置、测试或可重复的运行结果替换填写位；由维护者确认划分。没有实现的项目先写已确认的目标，未核实的事项注明缺什么依据，不把计划写成现状。

| 需要回答的问题 | 填写位 |
|---|---|
| 系统为谁解决什么问题？哪些事不由它负责？ | 【项目目标、使用者、系统边界】 |
| 怎样从真实入口观察到一项主要能力？ | 【触发和输入 → 参与单元及交接 → 可观察结果；影响结果的限制或失败】 |
| 哪些单元需要分别维护？它们依赖谁？ | 【经确认的单元、职责、依赖方向、模块 README 或源码入口】 |
| 修改一项能力时，怎样找到契约并验证改动？ | 【能力 → 契约归属、实现位置、实际验证入口；确有扩展点才写】 |

按实际能力或单元增行，不按目录数目补齐。只在需要解释独立契约时增加[子系统页](subsystems/README.md)；模块的用法与限制留在代码旁的 README。

## 共享研发工具链

- 先读[根 AGENTS](../AGENTS.md)决定修改范围与同步义务。外部约束保留在[研发输入](../研发输入/README.md)，本次目标和交付在[研发任务](../研发任务/README.md)，长期取舍和被否决的方案在 [Agent Note](../.agents/notes/README.md)。
- 写文档时按[文档标准](AGENTS.md)找归属；改动持久化结构时，查[持久化记录](persistence-changes/README.md)区分结构证据与兼容决策。
- 改代码前查[核心准则](core-guidelines/README.md)，评审特定工件时查[防御性模式](defensive-patterns/README.md)。[Cookbook](cookbook/README.md)保存可复验的操作步骤，[复盘](postmortem/README.md)保存单次事故与防止复发的措施。
- 运行检查从[工具模块](../scripts/README.md)进入；哪些文件受检查、哪些结果还需人判断，见[文档门禁](subsystems/documentation-gates.md)。这些是本地研发命令，不是项目构建、发布或部署入口。
