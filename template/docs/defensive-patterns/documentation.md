## DP-D1 同一事实的第二副本

- **要求**：把定义、默认值和限制留在拥有它的文档；其他页面只给读者需要的本地义务与导航。
- **缺陷**：定义变更后，副本仍给出旧答案。搜索命中两处时，读者不知道哪份有效。
- **判据**：用有辨识度的句子或字段列表搜索，能找到多份独立维护的相同定义。
- **边界**：生成区域、冻结快照或附出处的短引用不是独立维护的定义。
- **正确**：解释何时需要追踪旧格式，并链接[持久化记录](../persistence-changes/README.md)。
- **错误**：在使用页复制一套记录字段，再要求两处手工同步。

<a id="dp-d2-未经验证的操作性描述"></a>
## DP-D2 未经验证的操作性描述

- **要求**：以真实入口核验命令、选项、默认值与错误信息后再描述。未能执行时写清缺失的条件。
- **缺陷**：读者按错误命令或默认值操作，产生与文档不同的结果。
- **判据**：命令未注册，选项与帮助或实现不符，或宣称的运行结果没有相应环境下的证据。
- **边界**：提案可写候选接口，须标明它不是当前行为；无法本地复验的外部行为应注明依据与核验条件。
- **正确**：先从[命令清单](../../package.json)找到入口，再按文档的参数运行它。
- **错误**：看见相邻模块有安装流程，就把同一流程当成当前模块的用法。

<a id="dp-d3-已实现记录中的提案语气"></a>
## DP-D3 已实现记录中的提案语气

- **要求**：`implemented` Note 用现在时描述交付的行为、后果、实际验证与遗留。
- **缺陷**：已结束的迁移计划看起来仍是待执行的义务。
- **判据**：状态已是 `implemented`，却仍要求批准、保留计划章节，或把未验证的要求当作现状。
- **边界**：问题背景可说明最初动机；已知限制或暂缓事项可以保留，须与已交付行为区分。
- **正确**：在 `Testing` 中写实际运行过的检查和未覆盖的情况。
- **错误**：把提案中的验收清单整体搬入已实现记录，既不说明哪些检查跑过，也不写结果。
