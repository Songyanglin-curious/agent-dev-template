# 子系统

本目录按能力保存系统认知的第二层：每个页面描述一项能力的精确语义、数据结构、接口契约、生命周期和重要机制，供研究系统、设计方案和修改机制时查阅。

## 页面边界

- **写**：概念、类型、语义、接口契约、生命周期、行为约束、重要机制。
- **不写**：使用步骤和安装配置（→ 模块文档）、整体组成与依赖方向（→ [架构](../architecture.md)）、决策理由与被否决方案（→ Agent Note）。
- **类型归属**：类型定义记录在声明它的模块所属的子系统页面上；模块文档只链接类型，不复制定义。

## 什么时候建页

当一项能力具有跨模块的影响、需要精确契约才能安全修改，或者仅靠模块文档无法说明其语义时，建立子系统页。页面按能力组织，不按目录深度或代码包数量组织；没有独立契约的目录不建页。

一个子系统可以跨多个模块，一个模块也可以服务多个子系统。子系统页与哪些模块或模块组文档关联、如何检查，统一见[文档门禁](documentation-gates.md)。
