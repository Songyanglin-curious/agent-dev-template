# AGENTS.md — 文档标准

从[项目架构](architecture.md)和各目录的 README 查找文档。目录索引说明去哪里、什么时候读，不复述正文。页面组织与核验用 [doc-writing](../.agents/skills/doc-writing/SKILL.md)，编辑时应保留的契约用 [prose-standard](../.agents/skills/prose-standard/SKILL.md)。

## 文档结构

先确定读者要完成的事。教程按前置条件、动作、可观察结果排列；参考按读者要查的事实组织，不混入教学步骤。两者都有实质篇幅时拆开。每页只展开自己的主题：对子项说明职责与用途，细节链接到子项。模块与持久化记录依各自模板声明 `kind`，不要给普通目录索引加 `kind`。

## 层级分类法：一个事实一个归属

| 归属 | 写什么 | 不写什么 |
|---|---|---|
| [根 AGENTS](../AGENTS.md) 与子树 AGENTS | 全局或局部持续适用的指令、触发条件与规则入口 | 故事、例子、被链接规则的副本 |
| [架构](architecture.md) | 整体组成、依赖方向、扩展与修改入口 | 逐字段定义、决策历史 |
| [子系统](subsystems/README.md) | 一项能力的语义、契约、类型与生命周期 | 安装教程、跨系统地图 |
| 模块 README；按需建模块组 README | 模块说明使用方式、行为、职责、限制；模块组说明直接成员与协作 | 不逐目录建模块；组文档不复述成员契约 |
| [持久化记录](persistence-changes/README.md) | 历史结构、前驱、兼容决策与验证 | 当前运行时读写说明 |
| [核心准则](core-guidelines/README.md) / [防御性模式](defensive-patterns/README.md) | 设计时遵循的编号规则 / 按工件可识别的缺陷判据 | 单个业务对象的约定、事故时间线 |
| [Cookbook](cookbook/README.md) / [复盘](postmortem/README.md) | 可验证的重复操作 / 单次事故的经过、根因、保障 | 尚未验证的步骤、日常进度 |
| [研发输入](../研发输入/README.md) / [研发任务](../研发任务/README.md) | 外部原文与约束 / 本次目标、范围、交付与遗留 | 系统现状、长期设计理由 |
| [Agent Note](../.agents/notes/README.md) | 长期取舍、替代方案、后果与验证；归档是冻结的历史 | 任务清单或当前系统的权威说明 |
| 专项 Skill / 生成参考 | 场景工作流与判断标准 / 生成器拥有的穷举结果 | 产品契约 / 手工编辑的生成区域 |

已有项目接入时，`docs/handover/` 只暂存已核实、待明确归属的资料，不声明 `kind`；正式文档承接后连同临时入口移除。没有交接材料不建目录。见 [project-onboarding](../.agents/skills/project-onboarding/SKILL.md)。

<a id="writing-rules"></a>
## 写作规则

- 现状以代码、配置、测试和实际行为为据。命令、配置示例按展示方式验证；不能验证的写清条件，不把未知写成默认值。架构填写位供接入时替换，不把填写提示、虚构路径或指向未来文件的链接当项目事实。
- 段落一段一个物理行，使用软换行；保留代码、列表和表格的结构。仓库内用相对 Markdown 链接，历史证据用 tag 或 PR 编号。新增、移动或移除文档时同步直接上级 README 索引和受影响的入站链接。
- 模块及模块组 README 声明非空 `description` 和对应 `kind`。模块文档记录调用方能观察的行为、失败与限制；类型只在所属子系统页解释，已记录的契约变动时同批更新。模块门禁按 `kind` 发现，漏标导致漏检，需评审核对。
- 新增 kind 时一并提供独立模板、确定的文档归属与针对性检查。生成内容先更新生产者，再重新生成；区域登记及豁免说明见[文档门禁](subsystems/documentation-gates.md)。
- 写明谁在什么条件下做什么，保留时序、例外、后果和不明显的理由；删除测试走查、显而易见的控制流和推理过程。机械或局部编辑不另建 Note，维护已有归属即可。

<a id="wordcount-budgets"></a>
## 字数预算

[预算清单](../scripts/doc-budgets.manifest.json)按路径登记常驻文档及上限；未登记的文件不受数字门禁约束。`pnpm run verify-doc-budgets --list` 查看实际用量，CJK 字符逐个计数，其余按空白分词。新增受预算管理的文档时同时登记路径。超限先迁走不属于本页的细节，再压缩；仍需更多空间才说明理由并调整上限。达标后至少留 5% 余量，不为凑数字删契约。

## 冗余清单

- 按有辨识度的短语定位重复规则；只保留一个维护位置，其余用链接。不要手工复述可从权威源码、清单或生成器获得的穷举列表。
- 普通参考只描述当前行为。理由进 Note，事故经过进复盘；`implemented` 记录不留提案式计划和验收任务。冻结归档不参与措辞修订。
- 一段承载多个互不依赖的规则时拆分；删去不改变义务或判断的强调、开发过程和评审辩解。

## 仓库引用

文档修改运行 `pnpm run test:docs`；变更门禁逻辑另为可观察失败增加回归检查。链接有效不证明内容属实，结构通过不证明文档与行为同步，仍须评审归属、语义和覆盖范围。命令前提与检查范围见[文档门禁](subsystems/documentation-gates.md)。
