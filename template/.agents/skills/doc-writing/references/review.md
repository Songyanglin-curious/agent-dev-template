# 文档评审

## 新人能否独立使用

从入口出发，读者能否不读实现就判断何时选用、按什么顺序操作、怎样识别成功、失败和恢复？他能否在需要时找到负责该行为的模块、状态存放处及修改入口？缺少的操作事实补在使用位置；不影响选择的内部细节移到后面的实现说明或所属参考页。

## 证据与重复

用入口、代码、配置和实际执行给陈述定性，不以旧文或未落地的方案证明当前行为。模块 README 负责面向调用方的契约，组 README 只列直接成员并说明依赖方向和组合顺序。不要手写已有生产方的字段表或状态清单。搜索重复规则时核对每个匹配：若同一解释有多处权威，保留归属方，其他位置留链接；若约束在使用位置不可缺，则保留其行为后果。

## 预算与检查

`pnpm run verify-doc-budgets --list` 显示已登记页面的用量。超限先移走不属于该页的内容，再压缩重复；仍需增加预算时写明新增内容为何不可移出。预算是上限，不是删掉失败条件、例外或兼容义务的理由。

在目标项目根按[文档门禁](../../../../docs/subsystems/documentation-gates.md)运行相关检查。相对链接可解析不代表说明正确；记录实际走过的文档路径、观察结果、依赖不可用时的待核验项。归档 Note 是冻结快照，不为通过文档审计而改写其中的文字。
