# 归档 Agent Notes

先读 [Note 规则](../../notes/README.md) 和[归档说明](../../notes/archived/AGENTS.md)。以当前实现、测试、仍引用该决策的文档为证，不按字数、日期或数量配额判断。审计只给建议；取得修改授权后才移动或删除记录。

## 新 Note 是否取代旧决策

每次新增 Note，先在活跃记录中搜索同一决策或机制。已有记录仍持有同一决策的，只更新事实。新记录只取代其中一部分时，保留两份并交叉引用；完全合并前，确认新归属保留所有独有理由、替代方案、影响、验证与缺口，再修复旧记录的入站链接。不能靠 Git 历史保留唯一的理由副本。

## 按生命周期判断

| 生命周期 | 保留、归档或删除的依据 |
|---|---|
| `proposed` | 有效的提案继续评审；不再推进则说明原因，按规则转 `rejected`。不直接归档提案。 |
| `implemented` | 兼容承诺、归属、禁止行为、安全条件或替代方案仍能指导未来变更时保持活跃。仅记载局部展示或机械操作且无独立理由的记录可删除。完成的实质性决策仍有历史价值、但不再指导工作时才归档。 |
| `rejected` | 仍能阻止一个可信且有代价的错误时保留；理由已失效且不能再防止误用时删除记录并修复引用。 |

## 封存已实施记录

1. 把已实施记录从 `implemented/<class>/` 移至 `archived/<class>/`，保留文件名。保留 `Status: implemented`，紧接下一行加 `Archived: YYYY-MM-DD`（填实际归档日期）。这是唯一允许的正文改动。
2. 用当前权威替换活跃文档中的入站引用；只有刻意引用历史快照时才链接归档位置。不回写归档记录的出站链接。
3. 在项目根运行 `pnpm run verify-archived-agent-notes --write`；该模式校验已有封存记录，只为新增归档追加摘要。随后运行 `pnpm run test:notes` 检查分类、格式和冻结记录。

封存后不得重命名、移动、改写或删除记录。报告各项处置及依据、不确定的边界与实际校验，不把归档快照当作当前权威。
