# 清理编写过程残留

判断标准：没有会话、评审讨论和私人草稿，读者能否在当前项目中解析引用并核实断言？若不能，先找仍成立的行为、限制和理由，按[文字标准](../prose-standard/SKILL.md)保留完整命题，再删除其余叙述。普通文档写现状；时间线和被否方案分别属于复盘和 Agent Note。

## 找哪些问题

- 无法定位的草稿章节、审计代号或讨论结论：有稳定归属就链接，没有则写出能独立验证的规则或明确缺口。
- 分支、评审轮次和版本叙述：把结果写成当前行为；介绍改动的经过本身不属于公开接口说明。
- 自我辩护和控制流走查：保留不变量、失败后果和非显而易见的原因，删除显而易见的推导。
- 含糊保证、没有归属的规划和跨语言过程碎片：将实际义务放回任务或正式决策；不能验证时不要把承诺改成实现事实。

## 不要误删

实测数字及其测量条件、运行时新旧对象的切换、负向保证、抑制诊断的理由、当前可定位的标准章节或待办、复盘证据和已实施决策的验证结果，都可能带有时间或编号，但不是编写过程残留。保留调用方仍依赖的时序和例外。若删除一个从句会把未核验的行为说成既有功能，恢复其原有情态。

## 工作流程

1. 要求显式范围，评审只读，获授权才编辑。不进入版本库元数据、依赖目录、第三方代码或冻结的归档 Note；对生成内容只改生产方。
2. 先读所属规则和范围内最密集的页面，再按[检索原则](references/recall-batteries.md)找候选。用语义判断，不能把命中或零命中当作结论。
3. 检查每个引用和事实从句；删叙述不删约束。应由长期记录承担的理由按 [Note 规则](../../notes/README.md)处理，而非逐句搬运讨论。
4. 改后核对入站引用、文档门禁和相关测试；报告已处理项、刻意保留的证据、无法安全改写的内容及原因。
