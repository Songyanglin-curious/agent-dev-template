# 脚本与门禁

<a id="dp-s1-语料静默缩小"></a>
## DP-S1 语料静默缩小

**要求**：门禁扫描的文件集合只能由清单或 glob 决定，并在每次运行时报告实际检查数量。修改 glob、排除规则或目录布局后，用 `--list` 或摘要计数确认语料没有意外缩小。

**缺陷**：一个写错的正则或过窄的 glob 会让门禁检查零个文件，却仍然打印“通过”；结构约束从此失效，直到下一次事故才被发现。

**判据**：语料计数在无关变更后骤降；排除条件把整个目录排除；glob 中包含当前实现不支持的语法而没有报错；空语料时输出成功摘要。

**边界**：项目确实没有该类文档时，零计数是正确结果；此时摘要应显示零，并且对应清单或说明能解释原因。

**正确**：`verify-module-readmes: 3 module(s) and 1 module group(s) checked, all conform.`

**错误**：`verify-module-readmes: 0 module(s) checked, all conform.`，而仓库存在模块文档。

<a id="dp-s2-诊断不可定位"></a>
## DP-S2 诊断不可定位

**要求**：每条失败说明文件路径、行号（可得时）和期望值。聚合多个违规时逐条输出，不用“存在若干问题”代替。

**缺陷**：读者只能重跑脚本、阅读实现或在多个文件中搜索，自动化检查节省的时间被诊断成本抵消；Agent 更容易根据猜测修复错误的位置。

**判据**：失败信息没有路径；多个违规合并成一行；期望值与实际值缺失；失败来自共享模块却只显示共享模块的路径。

**边界**：清单级错误（如豁免条目失效）可以只报清单路径和条目键；仍须说明期望的修正动作。

**正确**：`docs/example.md:12: missing ## 已知限制与暂缓工作`

**错误**：`verify-module-readmes: some documents are invalid`

<a id="dp-s3-门禁行为与文档不一致"></a>
## DP-S3 门禁行为与文档不一致

**要求**：修改门禁的扫描语料、检查项、清单格式或退出语义时，在同一次变更中更新 `docs/subsystems/documentation-gates.md` 的对应行与相关 cookbook 步骤。

**缺陷**：文档描述的是旧行为，读者按文档判断门禁覆盖范围；新增检查被误认为已经覆盖模板，或在 CI 中意外失败却找不到依据。

**判据**：脚本新增或删除检查项，但子系统页的表格未变；清单字段变化而文档仍描述旧字段；新检查被加入总入口，但子系统页的清单没有对应行。

**边界**：修复诊断文案、重构共享函数而不改变可观察行为时，不要求修改文档；但若摘要或报告格式变化，仍需同步。

**正确**：新增门禁后同时更新 `docs/subsystems/documentation-gates.md`、`package.json` 与 `scripts/change-doc-rules.json`。

**错误**：只把脚本加入 `test:docs`，子系统页和模板仍停留在旧集合。
