# 研发任务

本目录记录**当前研发任务**：由外部输入或内部目标形成、需要具体实施和交付的工作。一项任务一份 Markdown，任务说明、必要进展和最终交付记录合并在同一文件中；不为每项任务建立目录。

## 与研发输入、Agent Note 的边界

- [研发输入](../研发输入/README.md) 保存外部原始需求、约束和参考资料，回答“依据什么”。
- 本目录保存任务目标、范围、验收、进展和交付，回答“这次做什么”。
- [Agent Note](../.agents/notes/README.md) 保存长期决策理由、替代方案和后果，回答“为什么这样决定”。
- 当前系统事实属于 `docs/` 或模块 README；最终交付记录属于任务文件，不另建交付报告。

任务通过相对链接引用输入，不复制原文。一个输入可以关联多个任务；任务也可以没有外部输入，例如内部技术改进。Agent Note 不记录任务进度，任务文件不记录长期设计理由。

## 目录与状态

```text
研发任务/
├── README.md
├── 进行中/
└── 归档/
    ├── 已交付/
    ├── 已放弃/
    └── 已替代/
```

| 状态 | 所在目录 | 进入条件 |
|---|---|---|
| `进行中` | `进行中/` | 已有目标、范围与验收条件，正在实施 |
| `已交付` | `归档/已交付/` | 已记录实际交付结果和验证结果 |
| `已放弃` | `归档/已放弃/` | 已记录放弃原因，不再继续 |
| `已替代` | `归档/已替代/` | 已有替代它的新任务，并在任务中链接 |

文件名使用 `YYYY-MM-DD-<简短标题>.md`；日期是任务创建日期。任务元数据只使用 YAML 的 `status` 字段，不引入任务编号、优先级、负责人、标签、评论或任务数据库。

## 生命周期

1. **创建**：从输入或对话整理目标、范围、验收和关联输入，在 `进行中/` 建立任务文件。
2. **推进**：在原文件中更新范围、进展和关联输入；不复制出第二份任务文件。
3. **交付**：填写最终交付结果、验证结果和遗留问题，把 `status` 改为 `已交付`，移动文件到 `归档/已交付/`。
4. **放弃**：在任务中增加 `## 放弃原因`，把 `status` 改为 `已放弃`，移动文件到 `归档/已放弃/`。
5. **替代**：在任务中增加 `## 替代关系`，链接替代它的新任务，把 `status` 改为 `已替代`，移动文件到 `归档/已替代/`。

状态变化时移动原文件，不复制文件。终态任务不回到 `进行中/`；需要继续工作时新建任务，并按实际情况让旧任务进入 `已替代/`。移动后要修复任务中的相对链接，确保输入、Note 和其他任务引用仍然有效。

## 文件结构

任务模板见 [task-management 模板](../.agents/skills/task-management/templates/task.md)。所有任务至少包含：

- `## 任务目标与背景`
- `## 关联输入`
- `## 工作范围与验收条件`
- `## 进展记录`
- `## 最终交付结果`
- `## 验证结果`
- `## 遗留问题`

`已放弃` 任务额外包含 `## 放弃原因`；`已替代` 任务额外包含 `## 替代关系`，并至少链接一个真实存在的任务文件。

## 检查

```sh
pnpm run verify-tasks
```

门禁检查任务目录、文件名、状态与目录一致性、必需章节、终态补充记录、替代任务引用和本地链接。它不判断任务是否真正完成，也不判断交付质量；这些由人和评审负责。

## 不做什么

不做任务看板、Issue 编号、标签、优先级、负责人、评论、自动状态流转或独立任务数据库。普通问答和机械修改不创建任务文件；需要时由 [任务管理 Skill](../.agents/skills/task-management/SKILL.md) 按需整理。
